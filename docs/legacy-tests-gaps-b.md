# Legacy integration tests — coverage gaps, group B

The legacy test files of group B (old program `Insurance-Software`, commit `17c1f1f`, `scripts/integration/`) and where each of their
cases is now proved in the C#/.NET + SQL Server program. "Covered before" names the test that already existed (coverage table v1);
every other test named here was added for this group. **NOT TESTED** and **N/A** never count as passed; the reason is given.

Rules of the port:

- The legacy amounts and day counts are kept. The claim actions and the cancellation writer take the day as a parameter, so their
  cases keep the legacy days (03.11.2026 …). The policy and payment actions read "today" from the database's clock
  (`DbOptions.Clock`, `docs/DEVELOPMENT.md` "Test clock"). The cases first ported before the clock existed run relative to the
  real today (policies from the first of today's month, receipts received and entered today); every case whose figures depend
  on a month boundary between two actions (a receipt in October, its allocation or reversal in November) or on a later day
  (an approval the next day, a card read on 04.11) also has a test on the legacy days, the clock standing on each action's day
  as the legacy `holder.__today` did; closed months in those tests come only from the real close.
- A failure half-way is produced by a test-only trigger on the test's own database (`Gaps.ArmAsync`: the n-th insert into a table
  fails within one transaction), as `ClaimWorld.ArmFaultAsync` does. Nothing bypasses a trigger; no closed month is reopened.
- The "a read fails once" and "a right removed between the quick check and the transaction" cases are left out of this document:
  another work package adds the failure-injection seam for them.
- Paths: `IT` = `tests/Insurance.Integration.Tests`, `WT` = `tests/Insurance.Web.Tests`.

Fixed with `LocaleFixed2`: the double's shortest round-trip digits, rounded half away from zero to the tetri, grouped. | `WT/Policies/GapsPrintPolicyTests.The_vehicles_value_a_stored_text_exactly_a_JSON_number_as_before_none_as_a_dash` failed on the unfixed code (`…408.00`); `A_JSON_number_is_shown_as_the_old_toLocaleString_did` (9 values, expected from Node 24). |
