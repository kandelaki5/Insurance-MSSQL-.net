# მონაცემების გადატანა PostgreSQL-იდან MS SQL Server-ზე

ეს ინსტრუქცია ძველი პროგრამის (Insurance-Software) ბაზის მონაცემებს ახალ ბაზაში გადაიტანს. ძველი ბაზა მხოლოდ იკითხება და არაფერი იცვლება.

## რა გადადის და რა არა

- **გადადის ყველა ცხრილი** ზუსტად ისე, როგორც ინახება:
  - id-ები და ისტორია;
  - პრემიის, გადახდებისა და განაწილებების ჟურნალები;
  - გრაფიკები და მათი კორექტირებები;
  - ზარალები, რეზერვები, ანაზღაურებები, ამოღებები;
  - გადაზღვევა, AML, პრეტენზიები, უფლებები;
  - აუდიტის ჟურნალი თავისი ნომრებით;
  - კურსები და დახურული თვეები.
- **ცნობარები** (ვალუტები, სახეობები, როლები, პარამეტრები, ნუმერაცია, პროდუქტები) იცვლება ძველი ბაზის ჩანაწერებით. ამის მერე ყველა id და მნიშვნელობა ძველისაა.
- **პაროლების ჰეშები** გადადის. ფორმატი (scrypt) იგივეა და ახალი კოდი მათ ამოწმებს. ეს ტესტით დადასტურებულია: ძველი კოდის შექმნილი ჰეშით შესვლა ახალ პროგრამაში მუშაობს.
- **სესიები არ გადადის:** გადატანის შემდეგ ყველა მომხმარებელი თავიდან შედის სისტემაში.
- **მიგრაციების ჟურნალი არ გადადის**, რადგან ახალ ბაზას თავისი აქვს.

## როგორ მუშაობს

1. **ერთი ტრანზაქცია.** ან ყველაფერი გადადის, ან არაფერი. თუ რომელიმე ცხრილი ვერ გადავიდა, ახალი ბაზა ზუსტად ისეთი რჩება, როგორიც იყო. ესეც ტესტით არის დადასტურებული.
2. **ძველი ბაზა ერთი მყარი მდგომარეობით იკითხება** (read only, repeatable read).
3. **ჩანაწერები ისე იწერება, როგორც არის**, დაცვის ტრიგერების გარეშე. ისინი ძველ ბაზაში წერისას უკვე შემოწმდა, ხოლო დახურული თვის დაცვა საკუთარ ისტორიას არ ჩაწერდა. შემდეგ ყველა კავშირი და შეზღუდვა ყველა ჩანაწერზე თავიდან მოწმდება (`WITH CHECK CHECK CONSTRAINT`).
4. **განმეორებითი გაშვება** მხოლოდ იმას ამატებს, რაც ახალ ბაზაში ჯერ არ არის. დუბლიკატი არ იქმნება. თუ არსებული ჩანაწერი ძველისგან განსხვავდება, გადატანა უარს ამბობს და არაფერს წერს.
5. **ყოველი გაშვება აღირიცხება** `core.data_import`-ში: საიდან (პაროლის გარეშე), როდის და რამდენი ჩანაწერი.

## ბრძანებები

კავშირები გარემოს ცვლადებით მიეცით. პაროლი არც ბრძანებაში წერთ, არც ფაილში.

```
export INSURANCE_MASTER_CONNECTION="Server=<სერვერი>;Database=master;User ID=<ადმინი>;Password=<…>;TrustServerCertificate=True"
export INSURANCE_ADMIN_CONNECTION="Server=<სერვერი>;Database=insurance_new;User ID=<ადმინი>;Password=<…>;TrustServerCertificate=True"
export INSURANCE_PG_CONNECTION="Host=<ძველი სერვერი>;Port=5432;Database=<ძველი ბაზა>;Username=<მხოლოდ კითხვის მომხმარებელი>;Password=<…>;SSL Mode=Require"

dotnet run --project src/Insurance.Tools -- create-database insurance_new   # ახალი, ცარიელი ბაზა
dotnet run --project src/Insurance.Tools -- migrate                         # სქემა
dotnet run --project src/Insurance.Tools -- import-postgres                 # გადატანა
dotnet run --project src/Insurance.Tools -- reconcile                       # შეჯერება
```

- ძველ ბაზასთან საკმარისია მხოლოდ კითხვის უფლების მქონე მომხმარებელი, მაგალითად `core_reader`.
- გადატანისას პროგრამაში არავინ უნდა მუშაობდეს.

## შეჯერება (`reconcile`)

ორივე ბაზა იკითხება და შედარდება:
- **ჩანაწერები:** ყოველი ცხრილის ჩანაწერების რაოდენობა და გასაღებების სრული სია;
- **პრემია:** პოლისის, ვალუტისა და თვის მიხედვით; სტრიქონისა და ჩანაწერის სახეობის მიხედვით;
- **გრაფიკი და დავალიანება:** გრაფიკი პოლისზე (კორექტირებებით), დაფარული თანხა შენატანზე, დავალიანება პოლისზე, გაუნაწილებელი ავანსი კლიენტზე;
- **გადახდები:** შემოსვლები, შებრუნებები და დაბრუნებები თვეების მიხედვით;
- **ზარალი:** რეზერვის დონე ზარალზე, ანაზღაურება ზარალზე, ამოღებები;
- **გადაზღვევა:** გადაცემული პრემია და საკომისიო ხელშეკრულებისა და თვის მიხედვით, ზარალის წილები;
- **სხვა:** რეგრესის მოძრაობები, თვეების სტატუსი, ნუმერაციის მდგომარეობა, კლიენტის სახელი და სეგმენტი, აუდიტის ჟურნალი;
- **კავშირები:** ყველა გარე გასაღები და შეზღუდვა ყველა ჩანაწერზე ძალაშია, და რეგრესის ფული მოძრაობის გარეშე არ არის.

ბრძანება ბეჭდავს `EQUAL` ან `DIFFERENT` ყოველ შემოწმებაზე. სხვაობისას აჩვენებს პირველ განსხვავებულ მნიშვნელობას და მუშაობას შეცდომის კოდით ამთავრებს.

## შემოწმება ფიქტიურ მონაცემებზე

- `tests/parity/legacy-world/build-world.ts` ცალკე PostgreSQL ბაზას ძველი პროგრამის საკუთარი ოპერაციებით ავსებს. ოპერაციები ცვლილების გარეშე სრულდება:
  - კლიენტები და რისკის შეფასება, გადაზღვევის ხელშეკრულება;
  - 8 პოლისი ლარში, დოლარსა და ევროში, დამტკიცებით;
  - გადახდები და მათი შებრუნება, გაუქმება, დაბრუნება, მათ შორის ფინანსური დირექტორის ავტორიზაციით;
  - ცვლილებები: მომატება და შემცირება;
  - ზარალები რეზერვით, ავტორიზაციით, ანაზღაურებით, შებრუნებით და ამოღებით;
  - ბენეფიციარი მესაკუთრე, ფმს-ის შეჩერება, სანქციების სია, მომხმარებელთა ჯგუფი და უფლებები, პრეტენზია, AML შემთხვევა;
  - სამი დახურული თვე.
- `tests/Insurance.Integration.Tests/DataMigrationTests.cs` ამ ბაზას ახალ SQL Server ბაზაში გადაიტანს და შეაჯერებს. ის ამოწმებს:
  - ყველა შემოწმება ემთხვევა;
  - განმეორებითი გადატანა ახალს არაფერს ამატებს;
  - შეცვლილი ჩანაწერი ჩანს შეჯერებაში და განმეორებითი გადატანა მას უარყოფს;
  - შეცდომით შეწყვეტილი გადატანა ბაზას უცვლელს ტოვებს;
  - ბაზაზე, რომელშიც უკვე სხვა მონაცემებია, გადატანა უარს ამბობს;
  - ძველი ჰეშით შესვლა მუშაობს.
- ტესტებს `INSURANCE_TEST_PG_WORLD` სჭირდება (იხ. `.env.test.example`). მის გარეშე ტესტები გამოტოვებულად (SKIP) ჩანს და არა გავლილად.
