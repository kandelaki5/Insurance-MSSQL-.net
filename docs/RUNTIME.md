# მხარდაჭერილი გარემო და ქცევის ერთნაირობა (Codex R04)

პროგრამა ერთნაირად უნდა მუშაობდეს Windows-სა და Linux-ზე და არ უნდა იყოს დამოკიდებული სერვერის ენაზე, რეგიონალურ პარამეტრებსა და დროის ზონაზე. ქვემოთ ჩამოთვლილია, რაზეა ეს დამოკიდებული და როგორ არის ეს დამოკიდებულება მოხსნილი.

## მხარდაჭერილი გარემო

| | |
|---|---|
| ოპერაციული სისტემა | Windows (IIS ან Kestrel) და Linux |
| .NET | 10, SDK 10.0.402 (`global.json`) |
| ბაზა | Microsoft SQL Server 2022, collation `Latin1_General_100_CS_AS_SC`, `READ_COMMITTED_SNAPSHOT ON` |
| სერვერის ენა, რეგიონი, დროის ზონა | ნებისმიერი: შედეგზე გავლენას არ ახდენს (ქვემოთ) |
| ძველი პროგრამის საცნობარო გარემო | Node 24.21.0 (Unicode 17, ICU 78.3), პროცესის დროის ზონა UTC, ენა en-US. ასეთ გარემოში მუშაობდა ძველი პროგრამა თავის სერვერზე. |

CI ორ გარემოს ამოწმებს:
- Linux: ყველა ტესტი, მათ შორის SQL Server, PostgreSQL იმპორტი და ბრაუზერი;
- Windows: ყველა წესი, რომელსაც ბაზა არ სჭირდება (Domain), ქართული რეგიონალური პარამეტრებით (`ka-GE`) და თბილისის დროის ზონით (`Georgian Standard Time`).

ორივე შემთხვევაში გამოტოვებული (SKIP) ტესტი CI-ს აჩერებს.

## 1. თბილისის დრო — ფიქსირებული UTC+04:00

**ძველი პროგრამა** თბილისის თარიღს სისტემის დროის ზონების ბაზიდან იღებდა (`Intl`, `Asia/Tbilisi`). შეჩერების ვადის დათვლისას შუაღამეს კი ყოველთვის `+04:00`-ით წერდა. ახალი პროგრამის პირველი ვერსიაც სისტემის ბაზას (`TimeZoneInfo`) იყენებდა.

**რა ხდებოდა:** Linux-ისა და Windows-ის ბაზები საქართველოს ძველ დროს განსხვავებულად აღწერს. 2005 წლამდე საქართველოში დრო რამდენჯერმე შეიცვალა: +03, +04, ზაფხულის დრო. ამიტომ Windows-ზე 1505 ისტორიული შემთხვევიდან 12-ში შეჩერების ვადა სხვაგვარად ითვლებოდა. ეს ის 12 შემთხვევაა, რომელიც Codex-მა 1994, 2001, 2004 და 2005 წლებზე იპოვა.

**ახლა:** ერთი წესი ყველგან, `Insurance.Domain.Common.TbilisiTime`. საქართველოს კანონიერი დრო არის UTC+04:00, ზაფხულის დროის გარეშე, 2005 წლის 27 მარტიდან. პროგრამის ყველა ოპერაცია ამ თარიღის შემდეგ ხდება. თარიღი, შუაღამე და „დღევანდელი დღე“ ამ წესით ითვლება. სისტემის დროის ზონების ბაზა საერთოდ აღარ გამოიყენება.

**შედარება ძველთან:**
- 2005-03-27 და შემდეგ ყველა შემთხვევაში შედეგი ძველი პროგრამის ზუსტად ტოლია, ყველა სისტემაზე.
- უფრო ძველი თარიღებისთვის ძველი პროგრამა იმდროინდელ საათს (+03 ან ზაფხულის +05) ურევდა +04:00 შუაღამეს. ზოგჯერ შედეგი უაზრო იყო. მაგალითად, 2005-03-18 13:10 UTC-ზე დაწყებული 48-საათიანი შეჩერება ძველში 7 საათში მთავრდებოდა: დათვლა გაიჭედა და უსაფრთხოების ზღვარზე შეწყდა. ახალი პროგრამა აქ სწორ 48 სამუშაო საათს ითვლის.
- ტესტი ძველთან ტოლობას ყველა შემთხვევაზე ამოწმებს. გამონაკლისია მხოლოდ ზუსტად ჩამოთვლილი 2005-მდელი შემთხვევები.

## 2. დიდი ასოები (toUpperCase) — ძველი პროგრამის საკუთარი ცხრილი

**ძველი პროგრამა** იყენებს JavaScript-ის `toUpperCase()`-ს, მაგალითად პოლისის/ზარალის ნომრის შედარებისას. მისი შედეგი Node-ის ვერსიაზეა დამოკიდებული: Node 22 (Unicode 16) და Node 24 (Unicode 17) 28 იშვიათ სიმბოლოზე განსხვავდება.

**ახლა:** ყველა სიმბოლო, რომელსაც დიდი ასო აქვს, ჩაწერილია ფაილში `src/Insurance.Domain/Common/JsUpper.txt`. ცხრილი აღებულია ძველი პროგრამის საცნობარო Node-იდან (24.21.0). C# მხოლოდ ამ ცხრილს იყენებს: არც .NET-ის, არც ოპერაციული სისტემის ცხრილს. ასე შედეგი არ იცვლება არც OS-ის, არც .NET-ის განახლებით. ცხრილს `tests/parity/generate/js-upper-table.ts` ქმნის.

## 3. ფორმა 6-ის სტრიქონების რიგი (localeCompare)

**ძველი პროგრამა** გადამზღვეველებს სახელით ალაგებდა სერვერის ენის მიხედვით. აქედან ორი სხვადასხვა რიგი გამოდიოდა:
- სერვერზე (en-US) ლათინური სახელები ქართულზე წინ იყო, ციფრები კი ყველაზე წინ;
- ქართულ Windows-ზე (ka-GE) ქართული სახელები ლათინურზე წინ ხვდებოდა.

ეს Node 24-ით შემოწმდა.

**ახლა:** რიგი სერვერის ენაზე აღარ არის დამოკიდებული. ის ყოველთვის ძველი პროგრამის სერვერის რიგს მიჰყვება (Unicode-ის ძირითადი წესი, ლათინური ქართულზე წინ). თანხებს ეს არ ცვლის, მხოლოდ სტრიქონების რიგს. **მფლობელისთვის ღია კითხვა:** სჯობს თუ არა ქართული სახელები ლათინურზე წინ? ასე ალაგებდა ძველი პროგრამა ქართულ კომპიუტერზე.

## 4. Excel-ის სვეტის სიგანე თარიღის სვეტში

**ძველი პროგრამა** სვეტის სიგანეს თარიღის ტექსტით ზომავდა (`String(date)`), ეს ტექსტი კი პროცესის დროის ზონაზეა დამოკიდებული. სერვერზე (UTC) ის 3 სიმბოლოთი მოკლეა, ვიდრე თბილისის დროით გაშვებულ კომპიუტერზე. ამიტომ Codex-ის Windows-ზე ზოგი სვეტი 23-ის ნაცვლად 26 სიგანის იყო.

**ახლა:** სიგანე ყოველთვის ძველი პროგრამის სერვერის (UTC) წესით ითვლება და დროის ზონაზე არ არის დამოკიდებული. ეს მხოლოდ სვეტის სიგანეა: უჯრის მნიშვნელობა და თარიღი იგივეა.

## ბაზა (SQL Server)

თბილისის თარიღს SQL-ში (`at time zone 'Georgian Standard Time'`) SQL Server-ის საკუთარი დროის ზონების ცხრილი ითვლის. ეს ცხრილი Windows-სა და Linux-ის SQL Server-ში ერთი და იგივეა.
