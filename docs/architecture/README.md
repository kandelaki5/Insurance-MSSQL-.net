## ნაბიჯების რიგი (თითოეული ცალკე commit, აწყობადი, ტესტებით; უკან დაბრუნება — commit-ის revert)

2. **B2 პირველი query:** `IPolicyListQuery` / `IPolicyCardQuery` Application-ში, Dapper-ის იმპლემენტაცია Infrastructure-ში; Razor-ის პოლისების სია/ბარათი და ახალი API ერთსა და იმავეს იყენებს (ციფრები იგივე — ტესტებით). — **შესრულდა:** `IPolicyListQuery` (გვერდი, რაოდენობა და ზუსტი თანხები ერთ ტრანზაქციაში; რიგი უახლესიდან, თანაბარ დროზე id-ით — გვერდები არ მეორდება და არ ტოვებს) და `IPolicyCardQuery` (ბარათის საერთო ციფრები; Razor-ის ბარათი მას თავისივე ტრანზაქციაში იძახებს, მკითხველზე დამოკიდებულს — უფლებები, ავანსი, დირექტორის მოთხოვნები — გვერდით კითხულობს). Razor-ის სია, Angular-ის ძველი `?handler=Data` და API ერთსა და იმავე query-ს იყენებს; ტესტი `tests/Insurance.Web.Tests/Api/PolicyApiTests.cs` (სამივე ერთსა და იმავე პოლისებს, რიგს და თანხებს აჩვენებს; შესწორების შემთხვევა 320/400).
3. **B3 შესვლა:** OpenIddict (Development/test-ში ნამდვილი login), BFF login/callback/logout, სესიის გაუქმება, Swagger Authorize (PKCE). არსებული scrypt-ჰეშები მუშაობს, დაზიანებული — უარყოფილია. — **შესრულდა ნაწილობრივ:** ჩაშენებული OpenIddict 7.7.1 (degraded mode, token store-ის გარეშე): მხოლოდ Authorization Code + PKCE S256 ("plain" აკრძალულია), კლიენტი მხოლოდ `insurance-swagger`, callback მხოლოდ ამავე საიტზე; კოდი 2 წუთი და ერთხელ (მიგრაცია 0014, `core.oidc_code_use` — მხოლოდ კოდის SHA-256); access token 30 წუთი, refresh token არ გაიცემა; ტოკენი ეკუთვნის იმ სესიას, რომელშიც გაიცა — გასვლის ან მომხმარებლის გათიშვის მომენტში API მას აღარ იღებს. Authorization header-ის არსებობისას მხოლოდ ის ითვლება. შესვლის გვერდი ბრუნდება მხოლოდ `/connect/authorize`-ზე (open redirect არა). Development-ს გარეთ ჩართვა მხოლოდ `Insurance:Oidc:Enabled=true` და Git-ის გარეთ მდებარე სერტიფიკატებით; კონფიგურაციის გარეშე provider, Swagger და bearer არ მუშაობს. Swagger UI `/api/swagger` (Development ან `Insurance:Api:OpenApi`). ტესტები: `tests/Insurance.Web.Tests/Api/OidcTests.cs` (7; უარყოფითი კონტროლი: ერთჯერადობის შემოწმების მოხსნით ტესტი ვარდება) და ბრაუზერში `BrowserSwaggerTests.cs` (Authorize → PKCE popup → `/api/v1/me` Bearer-ით). **დარჩა:** გარე provider-ის (Entra ID/Keycloak) BFF კლიენტი `core.app_user_login`-ით — ბრაუზერის სესია დღეს ისევ პროგრამის საკუთარი cookie-ია (ჩაშენებული provider-ის დროს ცალკე BFF-ის callback ახალს არაფერს მატებს); Data Protection გასაღებების შენახვა deploy-მდე.
4. **B4/B5 პირველი ვერტიკალი:** `/api/v1/policies` (სერვერული გვერდები, ძიება) და `/api/v1/policies/{id}`; Angular-ის პოლისების სია/დეტალი ახალ API-ზე, იმავე დიზაინით, ორივე თემით; ბრაუზერის ტესტი browser → BFF → API → query → MSSQL. — **შესრულდა:** Angular-ის store `/api/v1/policies`, `/api/v1/policies/{id}` და `/api/v1/me`-ს კითხულობს; თანხები `{minor, currency, scale}`-დან იწერება `money` pipe-ით (float-ის გარეშე, `frontend/src/app/money.ts`); შაბლონები და `styles.css` უცვლელია (დიზაინი და ორივე თემა იგივე). ბრაუზერის ტესტი `BrowserPolicyApiTests.cs` (1,234,567.88 USD, ნაშთი 265.00 GEL; ძველი `?handler=Data` აღარ გამოიძახება).
